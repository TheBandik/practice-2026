## Структура репозитория студента

Папка [`student-repo-demo/`](student-repo-demo/) содержит образец репозитория, который студент сдаёт по итогам практики.

## Что нужно сдать

1. **Отчёт** – 20–25 страниц по СК-СТО-ТР-04-1.005-2015
2. **Репозиторий** (GitHub или аналог):
   - Исходный код с декомпозицией на модули
   - Тесты и наборы тестовых данных
   - `Dockerfile`
   - `README.md` с инструкцией по установке, запуску и настройке

## Рекомендации по содержанию отчёта

Отчёт строится по разделам ниже – каждый раздел демонстрирует отдельный этап разработки:

| Раздел отчёта             | Что описать                                                         |
| ------------------------- | ------------------------------------------------------------------ |
| Введение                  | Цель и задачи практики                                             |
| Анализ задачи и алгоритм  | Обзор источников, математический аппарат, алгоритм и структуры данных |
| Обоснование средств       | Выбор языка, среды, библиотек; архитектура приложения              |
| Реализация                | Описание модулей, элементы управления интерфейсом                  |
| Тестирование и отладка    | Тестовая документация, юнит- и интеграционные тесты, тестовые данные |
| Руководство пользователя  | Руководство и инструкция по установке и развёртыванию             |
| Заключение                | Выводы по результатам работы                                       |

На что обратить внимание в содержательной части:

- **Алгоритмическое ядро** – основной акцент. Приведите **блок-схему** алгоритма, опишите его идею, обоснуйте выбор, дайте оценку сложности и поведение на граничных случаях.
- **Обоснование выбора средств** – оформите **сравнительной таблицей**: рассмотренные альтернативы языка, среды и библиотек, критерии сравнения и итоговый выбор.
- **Тестовые данные** – опишите наборы данных для штатных и граничных случаев; укажите, как они сгенерированы и что проверяют.
- **Тест-кейсы** – вход → ожидаемый результат → фактический результат; дополните **чек-листами** ручной проверки ключевых сценариев.
- **Скриншоты кода** – допустимы, но в небольшом объёме: только ключевые фрагменты (ядро алгоритма, нетривиальные места). Основной код — в репозитории, а не в отчёте.
